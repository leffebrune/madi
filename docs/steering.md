# 작업 중 추가 지시 (steer)

## 사용자 동작

- 전송 및 Ctrl+Enter는 실행 중에도 입력을 접수한다. 중지는 별도 버튼이다.
- 일반 메시지는 현재 세션의 추가 지시이며, 실행 중 `/new` 등 명령은 거절하고 초안을 유지한다.
- 대기 메시지는 입력창 위에 `전달 대기 중`으로 표시된다. 기존 assistant 스트림 사이에 삽입하지 않는다.
- 현재 모델 응답에 포함된 **도구 호출 묶음 전체**가 끝난 후 다음 모델 요청에 FIFO 순서로 추가한다. 아직 시작하지 않은 같은 묶음의 도구도 실행될 수 있다.
- 요청에 전달되거나 취소·오류 등으로 대기 상태가 끝나면 해당 안내를 제거한다. 전달 완료·저장 상태 안내 및 초안 복원 기능은 제공하지 않는다.
- 이미 수행한 도구 작업은 되돌리지 않는다. 중지·오류 후 재전송하면 작업이 중복될 수 있다.

## 구현 경계

- `WorkspaceCoordinator.SubmitPromptAsync`는 실행 완료가 아니라 **접수 완료**까지 기다린다. 세션 ID, 관찰한 RunId, 메시지 ID를 전달하며, start/close와 같은 admission gate를 사용한다.
- `SessionRuntime`이 세션별 입력함과 이벤트 저널을 소유한다. 메시지 ID로 중복 접수를 방지하고, 접수 이벤트가 전달 이벤트보다 먼저 기록되도록 보장한다.
- `AgentInputQueue`는 호출 직전 drain 및 정상 종료 시 empty-check/close를 원자적으로 수행한다. close 이후 입력은 유실하지 않고 다음 턴으로 넘긴다.
- Agent만 `pendingConversation`에 메시지를 추가한다. 모델 요청은 배열 스냅샷을 받는다. 도구 호출과 결과 사이에는 사용자 메시지를 삽입하지 않는다.
- 도구 없는 응답이라도 추가 입력이 있으면 assistant 항목을 마무리하고 모델 호출을 계속한다. 기존 도구 루프 감지 및 라운드 한도를 초기화하지 않는다.
- 저장 중 도착한 입력은 저장 성공 후 같은 세션에서 다음 턴으로 실행한다. 이전 실행을 완전히 해제하기 전까지는 **같은 RunId, 소유권 lease, Completion을 유지**하여 탭 닫기와 세션 점유가 후속 턴까지 포괄하도록 했다. 완전히 Idle이 된 뒤의 전송은 새 RunId를 받는다.
- 실패·취소·보호 중단에서는 자동 후속 실행을 하지 않는다. 아직 전달하지 않은 원문은 런타임 저널에 보존한다. provider가 요청 생성 전에 실패한 경우도 미전달로 정리한다.
- 한 저장 턴에 여러 사용자 메시지가 있을 수 있다. 모든 사용자 항목의 실제 ConversationIndex와 저장 상태를 관리한다. 보호 중단처럼 저장되었지만 성공하지 않은 경우도 구분한다.
- 기존 `IAgent` 구현의 호환 오버로드는 이전 RespondAsync를 호출한다. 입력함을 지원하지 않는 구현에서는 정상 턴 완료 후 런타임이 후속 턴으로 처리한다. 기본 Agent는 호출 경계에서 즉시 반영한다.

## 보존 범위

대기 입력과 전달 상태는 세션 런타임의 메모리 저널에 보존된다. 탭 내 세션 전환 및 화면 재생은 지원하지만 **프로세스 강제 종료나 앱 재시작 후 미저장 입력 복구는 지원하지 않는다**. 완료된 대화는 기존 CommitTurnAsync 트랜잭션으로 저장된다.

## 검증

- Core: 최종 응답 중 입력, FIFO, 요청 스냅샷, 순차/병렬 도구 묶음 경계, 종료 후 입력, 요청 전 실패, 라운드 한도.
- App: 저장 중 입력 및 중복 접수, 후속 턴 순서, 생성/저장 중 취소, 세션 전환 격리, 명령/오래된 RunId 거절, 종료 후 재개.
- Presentation: 대기 표시가 assistant 스트림을 분할하지 않음, 다중 사용자 항목 저장 처리, 전송과 취소 분리, 전달·중단 시 대기 안내 제거, 후속 턴 대기 안내 유지.
